# OneDev on Railway

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/onedev?referralCode=ZqgrJ0)

A core OneDev deployment for Railway with managed PostgreSQL and persistent application storage. It provides Git hosting, pull requests, issues, Kanban boards, packages, and project management without pretending that Railway can run Docker-based CI jobs.

## Architecture

- **OneDev 16.3.0** from the pinned official image
- **PostgreSQL** for relational application data
- **Persistent volume at `/opt/onedev`** for repositories, attachments, artifacts, and server state
- **HTTPS** through a Railway public domain targeting port `6610`
- **No job executor configured by default**

Both the PostgreSQL volume and the OneDev volume are required for a complete restore.

## First login

The template performs OneDev's supported unattended initialization:

- Username: `admin`
- Password: the generated `initial_password` service variable
- Email: `admin@example.com`

After signing in, change the administrator email and rotate the generated password if required by your operating policy.

## Git access

Git over HTTPS works through the generated Railway domain. Native SSH Git access is not enabled by the core template because it requires a separate Railway TCP proxy and a matching **Administration → System Settings → SSH Root URL** value.

## CI/CD limitation

Railway containers do not expose a Docker daemon and cannot run privileged nested containers. This template therefore leaves OneDev's executor list empty.

Supported next steps:

- Attach OneDev agents running on external Docker-capable hosts and configure a Remote Docker Executor.
- Configure a Remote Shell Executor for trusted jobs that do not require images or service containers.
- Use the separately maintained autoscaled-runner template when available.

Do not configure OneDev's Server Docker Executor on Railway; it will not work.

## Configuration

The service uses OneDev's documented PostgreSQL settings:

| Variable | Purpose |
| --- | --- |
| `PORT` | Railway routing target for OneDev HTTP on `6610`. |
| `hibernate_dialect` | OneDev PostgreSQL dialect. |
| `hibernate_connection_driver_class` | PostgreSQL JDBC driver. |
| `hibernate_connection_url` | Private Railway PostgreSQL JDBC URL. |
| `hibernate_connection_username` | PostgreSQL user. |
| `hibernate_connection_password` | PostgreSQL password. |
| `initial_user` | Initial administrator username. |
| `initial_password` | Generated initial administrator password. |
| `initial_email` | Initial administrator email. |
| `initial_server_url` | Canonical HTTPS URL generated by Railway. |

The `initial_*` variables only affect an empty installation.

## Backups and upgrades

Back up both PostgreSQL and `/opt/onedev`. Test restores before relying on a backup policy. The Docker image is intentionally pinned; upgrade it through a reviewed repository change after checking OneDev's release notes and backup guidance.
